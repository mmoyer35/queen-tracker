# Queen Tracker — App Store / Google Play setup

This turns the existing web app into installable **iOS** and **Android** apps using
[Capacitor](https://capacitorjs.com/). Capacitor wraps the *same* web code (index.html + js/)
in a native shell. Your Supabase backend and everything you've built stay exactly as-is.

- The web assets are **bundled into the app** (not loaded from a URL) — this is what Apple
  wants and what makes the app work offline.
- **No Mac required:** iOS is built on a cloud macOS runner (Codemagic). See the Codemagic section.
- GitHub Pages keeps working for the browser version — none of this breaks it.

## Accounts you'll need
- **Apple Developer Program** — $99/year (required to ship on the App Store).
- **Google Play Developer** — $25 one-time.
- **Codemagic** (or Ionic Appflow) — free tier is enough to start; builds iOS without a Mac.

## One-time project setup (run locally, in the repo folder)
```bash
npm install                 # installs Capacitor
npm run add:android         # creates the android/ native project
# iOS (android/ios native folders are generated by the build; ios needs macOS,
# which Codemagic provides — or run `npm run add:ios` on a Mac)
```
`npm run sync` re-copies the web app into `www/` and syncs it into the native projects
after any code change.

## Item 1 — Permissions (handled the native way) ✅

The app asks for three device permissions. Each is triggered by a standard web API inside
the native web-view, and the OS shows a real system prompt **only if** the native project
declares it with a user-facing reason. Those declarations are below.

| Permission | What triggers it | Why |
|---|---|---|
| Microphone | `getUserMedia({audio})` in the voice-note recorder | Dictate hive inspections |
| Camera | `getUserMedia({video})` in the in-app QR scanner + photos | Scan hive QR codes, take photos |
| Photo library | `<input type="file">` photo picker | Attach photos to a queen |

### iOS — add to `ios/App/App/Info.plist`
Paste these keys inside the top-level `<dict>` (exact user-facing strings — Apple shows them in the prompt):
```xml
<key>NSMicrophoneUsageDescription</key>
<string>Queen Tracker uses the microphone so you can dictate hive inspections as voice notes.</string>
<key>NSCameraUsageDescription</key>
<string>Queen Tracker uses the camera to scan hive QR codes and photograph your queens and comb.</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>Queen Tracker accesses your photos so you can attach pictures to a queen's record.</string>
<key>NSPhotoLibraryAddUsageDescription</key>
<string>Queen Tracker saves QR labels and exported photos to your photo library.</string>
```
Note: Capacitor 6's WKWebView supports `getUserMedia` for mic + camera as long as the two
usage strings above are present. `capacitor.config.json` already sets
`limitsNavigationsToAppBoundDomains: false` so the web-view can reach the Supabase API. Voice
transcription is called from a Supabase Edge Function, not the web-view, so the provider
(Groq, with OpenAI as fallback) never needs to be reachable from the device directly.

### Android — add to `android/app/src/main/AndroidManifest.xml`
Add these inside `<manifest>`, above the `<application>` tag:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" /> <!-- for reminders (Android 13+) -->
<uses-feature android:name="android.hardware.camera" android:required="false" />
```
Modern Android's photo picker needs no storage permission, so none is listed for photos.

> These files don't exist until you run `npm run add:android` / the iOS build. After that
> first `cap add`, apply the edits above once; they persist across future `cap sync` runs.
